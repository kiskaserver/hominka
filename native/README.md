# native — свій оверлей поверх гри (C++)

Це те, чого не вміє ні безрамковий режим, ні міст у RTSS: показати **справжній**
чат — з аватарками й емоутами — поверх гри у виключному повноекранному режимі.
Спосіб той самий, яким працюють OBS Game Capture, Discord і Steam: своя
бібліотека всередині процесу гри перехоплює показ кадру й домальовує поверх
нього.

Робиться у два кроки. **Цей каталог — крок 1.**

## Крок 1 (готово): каркас і доказ, що кадр наш

- `injector/injector.cpp` → `injector.exe` — кладе `overlay.dll` у процес гри
  (`VirtualAllocEx` + `WriteProcessMemory` + `CreateRemoteThread(LoadLibraryW)`).
  Розрядність цілі визначає `IsWow64Process2`; у 32-бітну гру йде x86-інжектор, у
  64-бітну — x64.
- `overlay/` → `overlay.dll` — перехоплює `IDXGISwapChain::Present` (DX11)
  підміною одного запису у vtable (`vtable_hook.h`) і малює тестовий прямокутник
  (`overlay_dx11.h`, `shaders.cpp`). Прямокутник — і є доказ: його видно поверх
  кадру гри, у її ж свопчейні.
- `common/guard.h` — **тверда відмова** інжектити у змагальні ігри з античитом
  (Valorant, CS2, Rust, Apex, EFT та ін.) і за наявністю самих античитів серед
  модулів процесу. Перевіряється ПЕРШОЮ, до будь-яких дій із процесом.
- `common/log.h` — журнал у `%TEMP%\hominka-overlay.log`: усередині чужого
  процесу більше сказати нікуди.
- `testhost/testhost.cpp` — крихітна гра-макет на DX11 для перевірки (у випуск не
  входить).

Що вже перевірено на живому прогоні: інʼєкція проходить, `Present`
перехоплюється («перший перехоплений Present — кадр наш» у журналі), фіолетовий
прямокутник Hominka зʼявляється поверх кадру тестового хоста; guard відмовляє
для `valorant.exe` з кодом 3 ще до пошуку DLL.

## Крок 2 (далі): справжній чат через спільну память

Python рендерить чат поза екраном (`QWebEngineView.grab()` → BGRA) і кладе кадр
у спільну память лише коли він змінився; DLL читає буфер, заливає в текстуру й
малює поверх кадру гри з альфою. Тоді ж — `EndScene` (DX9), черга команд (DX12),
`vkQueuePresentKHR` (Vulkan) і повне збереження/відновлення стану рендера.

## Як користуватися injector.exe

```
injector-x64.exe --exe game.exe            вкласти overlay.dll (поруч) у гру за іменем
injector-x64.exe --pid 1234                те саме за PID
injector-x64.exe --exe game.exe --dll D:\...\overlay.dll   свій шлях до DLL
injector-x64.exe --exe game.exe --check    лише перевірити, чи можна (не чіпає процес, DLL не треба)
```

Коди виходу (щоб програма могла сказати щось конкретніше за «не вдалося»):
`0` готово · `1` помилка в аргументах / немає overlay.dll · `2` процес не
знайдено · `3` **відмова: античит** · `4` не та розрядність DLL · `5` інша
помилка інʼєкції. Розрядність DLL і цілі мусять збігатися: у 64-бітну гру —
`injector-x64` + `overlay-x64.dll`, у 32-бітну — `-x86`.

## Збірка

Крос-компіляція під Windows з Linux через mingw-w64 у Docker — той самий підхід,
що й для Linux-версії програми. Windows SDK і Visual Studio не потрібні.

```powershell
cd native
.\build.ps1            # обидві розрядності → native\dist\
.\build.ps1 -Clean    # перебудувати образ з нуля
```

На виході: `overlay-{x64,x86}.dll`, `injector-{x64,x86}.exe` і `testhost-x64.exe`
(гра-макет для перевірки). Джерела компілюються ПІД ЧАС `docker build`, а бінарі
витягуються з образу через `docker cp` — жодного bind-mount: він на Windows
віддає файли з затримкою кешу, і збірка тихо брала вчорашній код (на цьому вже
згоріли — тому так).

## Межі й чесність (виноситься в інтерфейс на кроці 2)

- Функція — **для одиночних ігор**. У змагальних із античитами інʼєкція може
  коштувати бану, і guard туди не пускає взагалі.
- Discord і OBS живуть у білих списках античитів за домовленістю з їхніми
  розробниками; у нас такого списку немає.
- Непідписана DLL + `CreateRemoteThread` — привід для Defender/SmartScreen
  насторожитися. Підпис коду (OV-сертифікат) — окреме рішення й окремі гроші.
- Канал випуску — лише бета/дев, ніколи не stable: активні стрімери не мають
  отримати експеримент замість робочого чату.
